# 기록 운영

[개인정보와 업무 경계](privacy.md)와 [Git 절차](git-workflow.md)를 먼저 따른다.
공통 지침 뒤 MEMORY → INDEX → 관련 프로젝트 → snapshot.pending 순으로 필요한 범위만 읽는다.

## 저장

사용자가 저장을 요청한 결과만 요약한다. 기존 제목·목적·출처·미통합 세션을 비교하고 중복을 피한다.
프로젝트 소속은 system/project-registry.json으로 확인한다. 같은 폴더나 기술을 쓴다고 같은 프로젝트로 묶지 않는다.
명확한 신규는 catalog/register, 확인된 하위 작업은 bind로 등록한다. 모호하면 사용자에게 확인한다.
프로젝트 세션은 정본의 sync_workflow.py record로 저장한다. 각 세션 원문은 수정·이동하지 않는다.
정정은 원본 ID를 참조한 새 세션으로 남긴다. 프로젝트 정본 통합은 별도 요청 때만 한다.
프로젝트 밖의 목표·선호는 memory, 선택·이유는 decisions, 재사용할 지식은 notes, 미정리는 inbox에 둔다.

## 통합과 조회

snapshot의 상위 ID·expected·pending을 읽고 충돌 없는 이벤트만 integrate한다.
현재 상태를 갱신할 때는 날짜와 기존 결정·이력·출처를 보존한다. 과거·불확실 날짜는 history로만 연결한다.
정본 없는 과거 프로젝트와 의미 충돌은 pending에 남긴다. stale/busy이면 재조회하고 강제 반영하지 않는다.
조회 시 이미 통합된 상태와 pending 결과를 구분한다. 실제 실행한 검증과 다른 세션의 보고를 구분한다.

## 점검과 종료

[색인·읽기 전용 기억 점검](memory-maintenance.md)을 따른다. 주간 통합과 기억 점검은 별도 단계다.
중복·모순·오래된 내용은 검토 후보로 보고하고 자동 삭제·archive·재분류하지 않는다.
세션 종료·컨텍스트 압축 전 기록 가치가 있는 결정·결과·실패가 있으면 저장을 제안한다.
모든 대화를 자동 저장하지 않는다. 저장 요청 또는 이미 승인된 추적 범위에서만 실제로 기록한다.
