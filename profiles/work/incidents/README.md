# 실제 장애

고객·운영에 실제 영향이 난 사건을 기록한다. 잠재 결함은 findings에 둔다.
가치 있는 사건은 발생일·시스템·증상·원인·출처의 한 줄 로그를 남긴다.
핵심 기능 피해, 구조적 재발, 미완 후속 조치, 진단 난이도, 외부 책임 근거가 있으면 상세 문서를 작성한다.
본문은 요약·타임라인·영향·원인·당시 대응·재발 방지·미확인·관련 순서다.
심각도는 확인된 영향으로만 정한다. 사용자·고객 식별정보와 자격증명은 기록하지 않는다.
후속 결함은 findings에 두고 양방향 연결한다. 아래 로그와 상세 목록에 문서를 연결한다.

metadata는 status·updated·source 외 다음을 포함한다.

- severity: 심각 / 높음 / 보통 / 낮음
- state: 대응중 / 복구됨 / 사후분석완료 / 종료
- detected: YYYY-MM-DD HH:MM
- resolved: YYYY-MM-DD HH:MM 또는 미정
- owner: 내부 / 외부 / 혼합
- systems: 영향 시스템

파일명은 최초 인지일-짧은-이름.md다. 자동 archive·삭제·원인 확정은 수행하지 않는다.
