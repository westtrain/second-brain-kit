# 검증 범위

## v0.3.0 선택 기능

- Python 3.14 + 공식 MCP SDK 1.30.0에서 기본 회귀와 추가 검사를 포함한 142개 테스트 통과.
- 실제 stdio MCP 클라이언트로 초기화·도구 목록·검색·문서 조회를 확인하고, 조회 전용의 쓰기 호출 거부와 파일 해시 무변경을 확인.
- 가상 신규 브레인에서 MCP 등록 → 검토 브랜치 저장 → local main 저장 → snapshot → 통합을 확인.
- stale 통합과 remote 추가 후 쓰기를 거부하며, 같은 요청을 실패로 반환한 뒤 정본 커밋이 유지되는지 확인.
- 서로 다른 scope의 문서 ID·symlink·hardlink·경로 탈출·QMD 범위 밖 결과·오래된 평가 근거를 거부하는 검사 포함.
- QMD 2.8.3의 실제 CLI를 임시 설정/캐시와 가상 개인·업무 named index로 실행. 키워드 검색과 어댑터, 두 split의 평가를 확인.
- 가상 업무 development의 hit@5는 literal과 QMD 키워드 모두 2/3. 이 사례에서 키워드 엔진 교체만으로 의미 질문이 해결됐다고 주장하지 않는다.
- QMD hybrid는 고정 argv와 결과 검증 경로를 테스트했지만, 임베딩·질의 확장·재정렬 모델을 사용한 실제 종단 실행은 이번 검증에 포함하지 않음.
- MCP 지원 앱별 실제 자동 호출과 모델의 저장/통합 의미 판단은 SDK 프로토콜 테스트와 별개다.
- 실제 개인·회사 브레인과 AI 연결 설정은 이번 배포에서 변경하지 않는다. 공개 평가셋은 가상 예제이며 실제 자료로 생성하지 않았다.

기본 CI는 SDK 없이 실행하고, 별도 MCP CI는 의존성을 설치해 전송 테스트를 실행한다.
앱 연결·QMD 설치·인덱싱·MCP 쓰기 활성화는 모두 별도 선택이다.

## v0.2.0 기존 기능

## 직접 확인한 결과

- 핵심 저장·통합·등록부·경험 전달·백업·색인과 두 브레인 초기화 테스트를 가상 자료로 수행한다.
- 개인/업무가 서로 다른 Git 저장소이며 원격·회사 정보·프로젝트·실제 기록이 비어 있는지 확인한다.
- 네 provider의 스킬 설치와 config 경로가 동일한 두 저장소를 가리키는지 확인한다.
- 자동화의 current/history 반영, 후보 쌍 반영, stale·경로·ID·상태 검증은 실제 합성 Git 저장소로 테스트한다.
- 예약 plist 생성은 opt-in이며 테스트에서는 launchd에 등록하지 않는다.
- 공개 범위 검사에서 실제 기기 식별자·회사/개인 프로젝트·원본 데이터·기기 설정을 배제한다.

## 모델별 확인 수준

| CLI | 확인 결과 |
|---|---|
| Codex | 설치 도움말과 제한 옵션, 가상 JSON 실제 응답 확인 |
| Claude Code | 설치 도움말과 도구 비활성화 옵션, 가상 JSON 실제 응답 확인 |
| Gemini CLI | 공식 context/import 문서, 설치 도움말, 출력 envelope·공통 경로 테스트 통과. 실행 환경의 인증 미설정으로 실제 모델 응답 미확인 |
| Grok Build | 공식 AGENTS/skills 문서, 설치 도움말, 출력 envelope·공통 경로 테스트 통과. 실행 환경의 미로그인으로 실제 모델 응답 미확인 |

Gemini/Grok에 대한 위 인증 실패를 정상 응답이나 종단 검증 통과로 보고하지 않는다.
다른 사용자는 선택한 CLI에서 로그인한 뒤 automation/run.py check와 가상 프로젝트로 확인한다.
check 자체는 모델 인증 성공을 확인하지 않는다. 인증값을 이슈·설정 파일·공개 저장소에 넣지 않는다.

네 AI가 사용하는 기록 저장·통합 엔진은 같다. 모델의 자연어 해석·사실성·실제 운영 성공은 기계 테스트만으로 보장하지 않는다.
